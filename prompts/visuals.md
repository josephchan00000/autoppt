# 視覺頁 SOP — 什麼時候該放什麼圖

一份 60 分鐘的讀書分享，最沒說服力的就是「我自己用 matplotlib 畫的折線圖」。
聽眾看不出那條線是哪來的，也沒有理由相信它。

**判斷順序由上而下，能用上面的就不要用下面的。**

---

## 零、每一頁都要先問：這頁非得條列不可嗎？

實跑一本 21 章的書，產出 84 頁裡有 45 頁（54%）是條列頁，每頁 4–5 條。
每一頁都沒超過字數上限，但整份看下來就是一頁接一頁的項目符號，很悶。

**所以動筆之前先問三個問題，中一個就不要條列：**

| 問題 | 中了就畫成 |
|---|---|
| 這三點是不是「A 導致 B 導致 C」，或會繞回起點的迴圈？ | `flow` |
| 這三點是不是兩組東西在對照（書中值 vs 最新值、作者 vs 官方）？ | `table` 或 `split` |
| 這三點是不是散落在不同年代的幾個時間刻度？ | `timeline` |

都不是，才用條列，而且**每頁最多 3 條**（`config/project.yaml` 的
`bullets_l1_range`）。條數是上限不是目標，2 條講得清楚就不要湊成 3 條。

**連續最多 2 頁條列**（`max_consecutive_bullet_slides`），第 3 頁一定要是
視覺頁、引言頁或大數字頁。**全書視覺頁至少要佔四成**（`visual_slide_ratio_min`）。
這兩條 `08_qa.py` 的「節奏」檢查會抓。

## 優先序

### 1. 書中原圖（最高優先）

作者自己畫的圖，直接從書裡截出來放上投影片。

- 有「我把書翻給你看」的現場感，這是讀書分享最想要的效果
- 不可能畫錯，因為那就是作者的論據本身
- 出處只要寫「《書名》書中圖表，p.XX」

抽圖的方式：

```bash
python tools/extract_book_figures.py --input input/book.pdf --out work/08_bookfigs
```

它會掃過整本 PDF，把尺寸大於 300×200 的內嵌影像抽出來，檔名是 `pNNN.png`
（NNN = PDF 頁碼）。抽完**一定要自己開圖看過**，確認那是圖表而不是書衣、
作者照片或裝飾線條，再決定掛到哪一頁。

deck.json 的寫法：

```json
{ "kind": "chart", "image": { "path": "work/08_bookfigs/p163.png" },
  "title": "書中的圖 8：四十年下行", "subtitle": "美國長期利率，1945–2021（%）",
  "chart": null, "body": [], "sources": [{"label": "《時間的價格》書中圖表，p.163"}] }
```

### 2. 外部機構的原圖

書裡沒有、但 Stage 4 查到的外部資料，優先抓**那個機構自己畫的圖**，
不要拿它的數字自己重畫。聯準會的圖長得像聯準會，可信度是附帶的。

**做法是兩段式**：Stage 4 查證時只記網址（`figure_candidates` 的 `figure_url`），
之後在有對外連線的機器上一道指令全部抓回來。

```bash
python tools/fetch_source_figure.py --from-evidence          # 批次，推薦
python tools/fetch_source_figure.py --fred DGS10 --start 2015-01-01 \
    --out work/09_srcfigs/dgs10.png                          # 單張，FRED
python tools/fetch_source_figure.py --url "https://…/chart.png" \
    --out work/09_srcfigs/xxx.png                            # 單張，其他機構
```

批次模式會寫 `work/09_srcfigs/manifest.json`，已經抓到的不會重抓，
所以在雲端跑一次（多半全部失敗）、回本機再跑一次，就會補齊。

- FRED 有官方的出圖端點，指定序列代號就好（`--fred` 可給多個，會畫在同一張）
- 其他機構就找頁面上那張圖的實際網址
- **抓不到就往下一級走，不要硬拗**。有些機構的圖是 JS 畫的，沒有靜態檔
- **雲端環境（Cowork / Claude Code on the web）的出口是白名單**，機構網站幾乎
  全被擋（實測 FRED、Google、Wikimedia 都連不出去，只有 github / pypi 通）。
  這不是 bug 也不能繞，是組織的 egress policy。
  所以流程才拆成「雲端記網址、本機抓圖」兩段

抓回來之後同樣用 `image` 欄位掛上去，`sources` 寫機構全稱與日期。

### 3. 用圖形講機制：流程圖／時間軸／對照表／雙欄

書裡沒有圖、外部也抓不到，但**內容本身是一個機制或一組對照**時，
畫成圖形遠比畫成折線圖有用。四種都是原生 PowerPoint 圖形，不是圖片，
使用者可以自己拖、自己改字。

| 欄位 | 用在什麼內容 | 例子 |
|---|---|---|
| `flow` | 有先後順序的機制、或會自我強化的迴圈 | 坎蒂隆傳導順序、金融抑制迴圈 |
| `timeline` | 橫跨很長時間的幾個關鍵刻度 | 利率四千年 |
| `table` | 兩欄以上的結構化對照 | 書中值 → 最新值 |
| `split` | 正反兩方的對照 | 作者主張 vs 官方資料 |

```json
{ "kind": "chart", "flow": { "type": "chain", "per_row": 3, "nodes": [
    {"label": "零利率", "note": "資金成本近乎消失"},
    {"label": "利息不再當煞車", "note": "熊彼得的淘汰機制失效"},
    {"label": "生產力下滑", "note": "但 2023–2025 已回到 2%", "accent": true}
  ]}, "body": [{"level": 0, "text": "一行結語會畫在流程圖下方"}] }
```

- `type` 可為 `chain`（單向）或 `loop`（多一條回到起點的虛線）
- 超過 `per_row` 會換行，第二列自動改成由右到左的蛇行，換行箭頭因此是一條
  乾淨的垂直線，不會斜切過其他方塊
- `accent: true` 的那一格會反白成紅底，用來標「這一格是反例」或「這是重點」
- `timeline` 的 `events` 是 `{when, what, note}`；標註會上下交錯避免互相擠壓
- `table` 的 `widths` 是欄寬比例，例如 `[3, 3, 4]`
- `split` 的 `left` / `right` 各有 `title` 與 `items`，`accent: true` 的那一欄會用紅框

### 4. 引言頁與大數字頁（節奏工具，不是資料頁）

這兩種不放資料，放的是**節奏**。連續七八頁條列之後插一頁，聽眾會醒過來。

```json
{ "kind": "chart", "duration_sec": 20,
  "quote": { "text": "John Bull can stand many things,\nbut he cannot stand two per cent.",
             "zh": "約翰牛忍得了很多事，就是忍不了 2%。",
             "attrib": "Walter Bagehot（《時間的價格》p.94）" } }

{ "kind": "chart", "duration_sec": 20,
  "stat": { "value": "0.18%", "label": "瑞士國家銀行的股息殖利率（2018/04）",
            "note": "以當時股價回本近 600 年" } }
```

- 兩者都**不畫頁面標題**，整頁就是那句話／那個數字
- `duration_sec` 給 20 秒就夠，逐字稿只寫一句話的份量（約 73 字）
- 引言從 Stage 3 的 `quotes[]` 挑，大數字從 `data_points[]` 或
  Stage 4 的 `taiwan_lens[].supporting_data` 挑
- 一場 60 分鐘大約各放 3–4 頁，放太多就變成沒有內容

### 5. 自己畫的圖表（最後手段）

上面四級都不適用，而且這組數字**真的需要看到形狀**（趨勢、轉折、分布）
才有意義時，才用 `chart` 自己畫。

- 只能用 `bar` / `line` / `stacked`，**明令不畫圓餅圖**
- 每個數值都要來自同一個 `source_url`，混合來源要拆成多筆
- 如果那組數字用一句話就講得完（「從 7,200 億增加到 1.02 兆」），
  就不要畫圖，寫進內文或做成大數字頁

## 版面歸屬（哪一種視覺走哪一個版面）

| 視覺型別 | 版面 | 為什麼 | 主標／副標上限 |
|---|---|---|---|
| `image` `table` `split` | **內頁2-1（6）** | 主標副標走母片原生 placeholder，頁首與內容頁一致，整份簡報看起來是同一套 | 14 / 21 字 |
| `flow` `timeline` | 空白內頁（9） | 要完整高度才畫得開 | 20 / 30 字 |
| `quote` `stat` | 空白內頁（9） | 滿版設計，不畫頁面標題 | — |
| `chart`（自己畫的） | 空白內頁（9） | 圖本身就佔滿版面 | 20 / 30 字 |

走內頁2-1 的那三種，內容區是 8.98 × 4.96 in（比版面 9 少 1.2 吋高度），
換到的是母片原生的主標副標框。**因此標題字數上限跟內容頁一樣是 14 / 21**，
不是視覺頁的 20 / 30 —— 主標框是 36pt 單行，超過 14 字會折行壓到副標。

## 幾條實務規則

**一頁只放一個視覺。** 版面 9（空白內頁）沒有內文 placeholder，
`body` 會被畫成圖下方的一行註解，超過兩行就擠不下。

**視覺頁的標題寫結論，不是圖名。** ✗「美國十年期公債殖利率走勢」
✓「書中的圖 8：四十年下行」。圖名放副標，連同時間範圍與單位。

**不要重複。** 同一個數字在對照表講過，就不要再給它一頁圖表。
本專案最後砍掉兩張自製圖表，就是因為那兩個數字已經在「書中值 → 最新值」
對照表裡了。

**視覺頁的逐字稿要講畫面上沒有的那一層。** 書中原圖要唸出座標軸、
時間範圍與單位，指出最值得看的一兩個轉折；流程圖要講「為什麼這一步接到
下一步」，不要把每一格的 note 逐字唸一遍。

**字數上限看版面，不是看頁型**（`config/project.yaml` 的 `limits`）：
走空白內頁的視覺頁用自建 textbox，比較寬，主標 ≤20、副標 ≤30；
走內頁2-1 的 `image`／`table`／`split` 與所有內容頁一樣是主標 ≤14、副標 ≤21。
圖名寫在副標時要克制，機構全稱與精確定義放資料來源行就好，不用在副標重複。
