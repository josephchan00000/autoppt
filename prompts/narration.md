# Stage 7 — 逐字稿

為 `work/05_deck.json` 中的每一頁寫口語逐字稿，寫回該頁的 `narration` 欄位。

## 規則

- **語速基準：中文每分鐘 220 字。** 依 `duration_sec` 反推字數（70 秒 ≈ 250 字）
- 總時長目標依 `deck.minutes` 推算（60 分鐘 → 47–55 分鐘，留 5 分鐘 Q&A）。
  **時間是指引**：QA 對總時長與每頁字數只 WARN，超時就把次要證據頁移到附錄，不要刪內容
- **附錄頁（`role: appendix`）不寫逐字稿**，被問到再翻
- **口語，不是書面語。** 可以用「這邊」「其實」「我自己的經驗是」「講白一點」
- 每頁結構四段：
  1. **承接**上一頁的一句過場
  2. 這頁的**核心**
  3. **展開／舉例**
  4. 拋給下一頁的**鉤子**
- **投影片上已經寫的字不要逐條唸出來**，逐字稿要講的是「投影片上沒寫的那一層」：
  為什麼這個數字重要、這件事在台灣是什麼樣子、你自己怎麼看
- **角色決定這頁的逐字稿在做什麼**（`role` 欄位）：

  | role | 逐字稿要做的事 |
  |---|---|
  | `author` | 把作者介紹成一個人：他在哪裡工作過、寫過什麼、站哪一邊、為什麼在零利率年代寫這本書；掌聲與批評都講 |
  | `summary` | 用一分鐘把整場講完一遍：主張、最有力的證據、對長期投資的意義。聽眾中途離場也帶得走 |
  | `map` | 唸分部與章名，告訴聽眾今天走哪幾章、跳過哪幾章（跳過的在附錄） |
  | `part` `divider` | 一句話：這一章／這一部作者要回答什麼問題，20 秒內 |
  | `outline` | **用這章的故事開場**（`story_hint`）：場景 → 轉折 → 作者的結論，再把大綱三步講成一段推理。QA「故事」會檢查逐字稿有沒有講到故事的人物 |
  | `evidence` | 講畫面上沒有的那一層：座標軸與時間範圍、最值得看的轉折、這張圖撐住大綱的哪一步 |
  | `today` | 把書中值和最新值唸清楚（單位、時點、出處），說這章寫完之後世界變了沒 |
  | `implication` | 落到長期投資的動作：配置、折現率假設、風險預算、持有期間，一句講清楚 |
  | `counter` | 語氣要平，講反方時不要護航作者，也不要翻臉；作者的立場（作者頁）可以拿來對照 |
  | `closing` | 回到 `summary` 的主張，一句收束，然後開放提問 |
- **數據頁必須把數字唸清楚**並說明單位與時間點
  （「百分之十二點四，這是二〇二四年底的數字，資料來自主計總處」）
- **章節頁籤頁的逐字稿只要 20–30 秒的過場**
- **影片頁（`kind: video`）只要 30–120 字的過場詞**：進場一句（為什麼要看這段）、
  收尾一句（看完要注意什麼）。`duration_sec` 是播放長度，不要照它反推字數
- 標註提示，用方括號，不計入字數：
  `[停頓]` `[看向聽眾]` `[這裡可能會被問：...]` `[如果時間不夠可跳過]`

## 【去 AI 味】← 使用者退過一次的地方

逐字稿是講出來的，不是唸出來的。三個具體要求：

- **句子要有主詞。** ✗「低利率造成資本錯置」 ✓「利率壓到零，錢就留在不該留的地方」
- **不要把投影片上的冒號句唸一遍。** 投影片寫「古德哈特法則」，
  逐字稿要說「這個法則的意思是，一個指標一旦變成目標，它就不準了」。
- **一段裡最多一個英文詞**，而且唸完要補一句中文解釋。
- 可以用「其實」「反過來說」「講白一點」「你看」，也可以反問聽眾。
  但每一個判斷後面要緊接著說根據什麼。

## 語氣 ← 動筆前先讀

`work/05_deck.json` 的 `meta.tone_directive_narration` 是這次選定的語氣規則，
**整份逐字稿照著寫**。上面那條「口語，不是書面語」是通則，
但「專業嚴謹」這種語氣對口語的容許範圍比較窄，以 tone_directive 為準。

語氣規則的原文在 `config/project.yaml` 的 `tone_presets`。

## 語言

繁體中文。專有名詞第一次出現要唸全稱並解釋。
不使用對岸用語。不要念稿感太重的排比句。

## 輸出兩份

1. 寫回 `slide.notes_slide.notes_text_frame`（`06_build_pptx.py` 會從 deck.json
   的 `narration` 欄位一併處理，你只要把文字寫進 deck.json 即可）
2. `07_build_script.py` 用 python-docx 產 `output/FH_書名_逐字稿.docx`：
   - 表格式版面：左欄頁碼 + 投影片主標，右欄逐字稿
   - 每章起始插入分頁
   - 頁首寫累計時間軸（「第 12 頁 / 累計 14:30」）
   - 文末附「預期提問與備答」一節（從各章 `counterpoint` 生成）

## 寫完自己檢查

- [ ] 有照 `meta.tone_directive_narration` 的語氣寫？
- [ ] 每頁字數 = `duration_sec` × 220/60，誤差在 ±25% 內？（超出只 WARN）
- [ ] 總時長落在目標區間？（超出只 WARN；超時先把證據頁移到附錄）
- [ ] 每一章的大綱頁用故事開場？意涵頁落到長期投資的動作？
- [ ] 作者頁的每一句都對得到 work/04_author.json 的來源？
- [ ] 附錄頁沒有寫逐字稿？
- [ ] 沒有把投影片上的 bullet 逐條唸一次？
- [ ] 數據頁有唸出單位與時間點？
- [ ] 頁籤頁夠短（20–30 秒 ≈ 75–110 字）？

跑 `python scripts/08_qa.py --check-narration` 驗證字數與總時長。
