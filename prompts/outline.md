# Stage 5 — 投影片文案潤飾

`05_outline.py` 已經把 digest + evidence 合成 `work/05_deck.json` 骨架，
並算好頁數預算與版面分派。**你的工作是潤飾文案，不是重排版面。**

不要改動：`id`、`layout`、`kind`、`ch_id`、`sources[].url`。
可以改動：`title`、`subtitle`、`body`、`sources[].label`、`duration_sec`。

## 【標題】

- 主標一律寫成「**有結論的句子**」，不是名詞標籤
  - ✗「風險管理」
  - ✓「風險預算該分配在部位，不在情緒」
  - ✗「資產配置的重要性」
  - ✓「配置決定九成績效，選股貢獻扣成本後歸零」
- 主標 ≤ **18 字**；副標 ≤ **28 字**，副標負責補「為什麼／所以呢」
- 同一章內的主標不要重複句型，連續三頁都用「X 才是 Y」會很呆

## 【內文】

- 每頁第一層要點 **3–5 條**，每條 ≤ **40 字**，不寫完整句號結尾的長句
- 層級**最多 2 層**（level 0 與 level 1），不准出現第 3 層
- 每頁總字數 ≤ **160 字**（4:3 版面，24pt 內文，超過就爆版）
- 每頁**至少有一個「具體物」**：數字、年份、案例名、金額、比例。
  全部都是抽象概念的頁面一律重寫。
  - ✗「市場情緒會影響投資決策，投資人應保持理性」
  - ✓「2020/3 台股單月跌 14%，散戶淨賣超 380 億，三個月後全數回補」
- 第二層（level 1）只在需要舉證或補數字時使用，不要每條都掛一個第二層

## 【資料來源】

- 每一頁都要有 `sources`（封面／頁籤／結尾除外）
- 書內容寫「《書名》p.XX」
- 外部資料寫「機構名（YYYY/MM）」
- 外部資料**同時保留 `url` 進 deck.json**，供 QA 檢查，但投影片上只印機構名與日期
- 不要把 URL 寫進 `label`

## 【語氣】← 這次要用哪一種，看 deck.json

`work/05_deck.json` 的 `meta.tone_directive_slide` 就是這次選定的語氣規則，
**動筆之前先讀它**，整份稿子照著寫。三種語氣（專業嚴謹／輕鬆口語／說故事）
對主標句型、可不可以用轉折詞、數字要怎麼呈現的要求都不一樣。

語氣規則的原文在 `config/project.yaml` 的 `tone_presets`，要改措辭改那裡。

## 【語言】

- 繁體中文為主，專有名詞保留英文原文，首次出現寫「中文（English）」
- 不使用「賦能、抓手、閉環、顆粒度、打法、復盤、落地性、用戶、信息、質量」
  這類對岸用語

## 【各種頁型的文案重點】

| kind | 重點 |
|---|---|
| `cover` | 主標＝書名；副標＝這本書的一句話定位（不是副書名） |
| `toc` | 用章節群組名，不要照抄原書目錄；每條要看得出「這段要回答什麼問題」 |
| `divider` | 只有章節名。不要加內文 |
| `content` | 主標＝結論句；body 3–5 條；至少一個具體物 |
| `chart` | 主標＝這張圖要說的結論（不是圖名）；副標補資料範圍與單位；body ≤ 2 條 |
| `closing` | 一句話收束全書 + Q&A |

特別注意三種頁：
- **「為什麼讀這本書」**：要講「這本書解決了我們手上哪個具體問題」，不要寫書評
- **「我的異議」**：從各章 `counterpoint` 綜合，要有立場，不要寫「本書仍有參考價值」
- **「可落地的行動」**：每條都要是「明天就能做」的動作，不是原則
