# 示意圖：自己畫，不要去找圖

章名頁籤右側那一格要放東西。優先序：

1. **使用者自己找的照片** `work/09_photos/<頁面 id>.jpg` —— 真實的人與地點最有說服力
2. **你自己畫的 SVG** `work/10_illus/<頁面 id>.svg` ← 這份文件講的就是這個
3. 兩個都沒有 → 程式自動畫一張文字場景卡（年份／人物／地點），不會開天窗

雲端環境抓不到圖（Commons、機構網站、圖庫都被 egress 白名單擋掉，回 403），
**不要花時間試**。自己畫的向量圖沒有連線問題，也沒有版權問題。

---

## 一句話規格

每一章一個 SVG，檔名 = 該章**章名頁籤那一頁的 `id`**（在 `work/05_deck.json` 裡，
例如 `s009.svg`）。畫該章故事的**場景或核心物件**，不畫人臉、不寫字。

```bash
python tools/make_illustrations.py --status     # 哪幾章還沒畫
python tools/make_illustrations.py --contact    # 轉 PNG + 出一張總覽圖
```

**畫完一定要開 `work/10_illus/contact.png` 自己看過。** 這是唯一的品管。

## 畫布與配色

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 460 500" width="460" height="500">
  <rect width="460" height="500" fill="#F4F1EA"/>
  <!-- 圖在這裡。安全範圍 x 50–410、y 70–440 -->
  <rect x="0" y="478" width="460" height="22" fill="#B82837"/>
</svg>
```

| 用途 | 色碼 | 什麼時候用 |
|---|---|---|
| 紙底 | `#F4F1EA` | 背景，跟卡片同一個米白 |
| 復華紅 | `#B82837` | **這一章的重點**，一張圖只紅一個地方 |
| 墨黑 | `#3A3A3C` | 結構、輪廓、建築、山形 |
| 淺灰 | `#C9C2B4` | 次要的線、陰影、退到背景的東西 |

直式框，比例約 0.92:1。**線寬 10–15**，比想像中粗——這張圖在投影幕上只有 7 公分寬。

## 畫得好的 vs 畫不好的

這是實跑出來的結論，不是理論：

| ✓ 畫得好 | ✗ 畫不好 |
|---|---|
| 建築（柱列、山形牆、門面） | **人臉、人像** |
| 器物（試管、天秤、沙漏、硬幣、麥克風、罐子） | **動物**（第一版畫了一隻烏鴉，變成一團血塊） |
| 山形、海平面、冰山（多邊形） | 手、衣服、任何有機曲線 |
| 圖表（座標軸、曲線、靶、箭頭） | 複雜場景（街景、人群、室內） |
| 紙張、書、小冊子（矩形＋色條） | 漸層、陰影、透視 |

**規則：只用直線、圓、矩形、多邊形與簡單貝茲曲線能畫出來的東西。**
想畫的東西如果需要「畫得像」，就換一個能代表它的物件。

範例——同一個故事的兩種選法：

- 故事是「懷特在傑克森霍爾警告風暴」→ ✗ 畫懷特　✓ 畫**山巔上一支紅旗**
- 故事是「庫普在攝影棚唱歌被拍到」→ ✗ 畫庫普　✓ 畫**一支廣播麥克風＋音波**
- 故事是「喬治亞州一對老夫妻存款歸零」→ ✗ 畫老夫妻　✓ 畫**罐子裡最後一枚硬幣**

## 怎麼挑那個物件

從該章的故事（`work/05a_guide.json` 選的那一則）裡找**一個名詞**，
它要能同時說出「發生什麼事」與「作者的判斷」：

| 章的重點 | 物件 | 紅色放在哪 |
|---|---|---|
| 銀行倒閉 | 古典銀行立面 | 一道裂縫貫穿 |
| 量尺變成目標就失效 | 同心圓靶 | 靶心被搬到圈外 |
| 隱藏的債務 | 冰山 | 水面下那一大塊 |
| 利息是時間的價格 | 天秤 | 一邊是硬幣 |
| 錢會生鏽 | 硬幣 | 貼上去的印花 |
| 市場翻轉 | 座標軸曲線 | 翻下去的那條 |

一張圖只紅一個地方。紅色就是聽眾第一眼要看到的東西。

## 步驟

1. `python tools/make_illustrations.py --status` 看哪幾章要畫
2. 讀該章的故事（`work/03_digest/chNN.json` 的 `stories`），挑一個物件
3. 寫 `work/10_illus/<頁面 id>.svg`
4. `python tools/make_illustrations.py --contact`
5. **開 `work/10_illus/contact.png` 看**。看不懂那是什麼，就重畫成更簡單的物件
6. `python scripts/06_build_pptx.py` → 翻 PDF 確認在版面上的大小對

一次畫完全部再看總覽圖，比一張一張畫有效率——問題通常是整組的
（線太細、留白太多、紅色用太多處）。

---

## 不要做的事

- 不要畫人臉、人像、動物
- 不要在 SVG 裡寫中文字（MuPDF 轉檔時字型不一定在，會變成方框）；
  文字交給投影片，圖下那行「年份　人物｜地點」是程式自動加的
- 不要用漸層、陰影、半透明堆疊——投影幕上只會變灰
- 不要一張圖用三種以上的顏色
- 不要把整章的論證畫成流程圖：那是內頁的事，頁籤只要一個意象
- 不要為了畫而畫：這一章的故事如果沒有具體的物件，就讓程式畫文字場景卡
